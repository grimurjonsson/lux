<task type="auto" tdd="true">
  <name>Task 1: Implement --list-profiles and --list-colors commands</name>
  <files>src/config.rs, src/main.rs</files>
  <behavior>
    - --list-profiles with no config file -> prints "No config file found" with XDG path hint and exits 0
    - --list-profiles with config containing profiles -> prints each profile name + rule count, then config path
    - --list-profiles with config but no profiles -> prints "No profiles defined" and config path
    - --list-colors -> prints each named color rendered in that color (e.g., "red" printed in red)
    - --list-colors -> includes styles section (bold, dim, italic, underline rendered)
    - --list-colors -> includes note about hex (#rrggbb) and numeric (0-255) formats
    - --list-colors forces color output even when piped (not affected by isatty check)
    - Both commands exit immediately without reading stdin
  </behavior>
  <action>
1. Add `pub fn print_profiles(config_path: Option<&Path>) -> Result<()>` to src/config.rs:
   - Load config from explicit path or default path
   - If no config found: print "No config file found." and "Default location: {default_config_path()}" then return Ok
   - If config found but no profiles: print "No profiles defined in {path}"
   - If config found with profiles: for each profile sorted alphabetically, print "{name} ({N} rules)" then print blank line and "Config: {path}"

2. Add `pub fn print_colors()` to src/config.rs (or a new display helper section):
   - This function forces color output regardless of terminal detection. Use `owo_colors::OwoColorize` with `Style` objects directly -- since --color=always is the context, create Style objects and use `.style()`.
   - Print sections:
     - "ANSI Colors:" header, then each of the 16 ANSI colors printed with their name rendered in that color (e.g., `"  red".red()`)
     - "Extended Colors:" header, then each extended color (orange, pink, grey, purple, teal, lime, brown, olive, coral, lavender) rendered in its color
     - "Styles:" header, then each style (bold, dim, italic, underline) rendered with that style applied to sample text
     - "Formats:" header, then notes: "  #rrggbb  Hex RGB (e.g., #ff0000)", "  0-255    256-color index (e.g., 196)", "  bg:COLOR Background (e.g., bg:red, bg:#00ff00)"
   - Use `owo_colors` set_override(true) at the start to force color output even when not a terminal (locked decision: --list-colors forces color). Reset with set_override(false) after printing. The `owo-colors` crate supports `owo_colors::set_override(true)` when the `supports-colors` feature is enabled (which it is in Cargo.toml).

3. Replace the placeholder early-exit stubs in src/main.rs `run()`:
   - For `cli.list_colors`: call `config::print_colors()` then `std::process::exit(0)`
   - For `cli.list_profiles`: call `config::print_profiles(cli.config.as_deref().map(Path::new))?` then `std::process::exit(0)`
   - These checks must happen BEFORE config loading for the main pipeline (list_colors doesn't need config at all)
  </action>
  <verify>
    <automated>cargo test --lib config::tests</automated>
  </verify>
  <done>--list-profiles prints profile names with rule counts and config path. --list-colors shows all colors rendered in their own color with styles and format notes. Both exit immediately. --list-colors forces color even when piped.</done>
</task>
