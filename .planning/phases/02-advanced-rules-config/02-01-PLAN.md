  <name>Task 1: Rewrite Engine::apply() with span-based coloring</name>
  <files>src/engine.rs</files>
  <behavior>
    - Match-scope rule: line "2024 ERROR: fail" with rule `ERROR:red:match` -> only "ERROR" is red, rest is plain
    - Capture-scope rule: line "user=42 action=login" with rule `user=(\d+):blue:cap1` -> only "42" is blue
    - Line-scope rule: line "ERROR: fail" with rule `ERROR:red:line` -> entire line is red (regression check)
    - Multi-rule overlap: rules `\d{4}:blue:match` and `ERROR:red:line` on "2024 ERROR: fail" -> "2024" is blue, rest of line is red
    - Priority conflict: two rules both matching "ERROR", priority 0 (blue) and priority 1 (red) -> "ERROR" region is blue
    - Missing capture group: rule `(foo):green:cap2` on "foo bar" -> no coloring for that rule (silently skipped)
    - No match: line with no matching rules -> returned unchanged
    - Color disabled: any line -> returned unchanged
    - Empty rules: any line -> returned unchanged
  </behavior>
  <action>
Rewrite `Engine::apply()` in src/engine.rs to use span-based coloring:

1. Define a `Span` struct with `range: Range<usize>`, `style: Style`, `priority: usize`.

2. For each rule, check if it matches the line. Based on scope:
   - `Line` -> span covers `0..line.len()`
   - `Match` -> use `pattern.find(line)`, span covers `m.start()..m.end()`
   - `Capture(n)` -> use `pattern.captures(line)`, get group `n`. If group missing, silently skip (per locked decision).

3. Build a per-byte-position style map: `Vec<Option<(usize, Style)>>` where usize is priority. Sort spans by priority ascending (lowest number = highest priority). For each span, fill positions that are still `None`.

4. Coalesce consecutive positions with the same style into segments. Render each segment with `owo_colors::OwoColorize::style()` or plain text.

Key implementation notes:
- Use `owo_colors::Style` comparison: check if two styles are the "same" by comparing the priority index stored alongside, not the Style struct itself (Style may not impl PartialEq).
- Regex match boundaries are guaranteed UTF-8 safe, so byte slicing is safe.
- For Line scope, if rule matches, use `pattern.is_match()` (cheaper than `find()`), then create span `0..line.len()`.

Update existing tests: the `test_first_matching_rule_wins` test needs updating since the engine no longer does first-match-wins for the whole line. Replace with tests for the span model. Keep `test_no_match_passthrough`, `test_no_rules_passthrough`, `test_color_disabled_passthrough`, `test_default_rules_*` tests (these should still pass since default rules are all line-scoped).
  </action>
