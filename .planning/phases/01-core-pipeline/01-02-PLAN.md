  <action>
Create `src/cli.rs` with clap derive:
```rust
#[derive(clap::Parser)]
#[command(name = "ctail", about = "Colored tail - instantly readable log output")]
pub struct Cli {
    #[arg(short = 'r', long = "rule", action = clap::ArgAction::Append)]
    pub rules: Vec<String>,

    #[arg(long, default_value = "auto")]
    pub color: ColorChoice,
}

#[derive(Clone, clap::ValueEnum)]
pub enum ColorChoice { Auto, Always, Never }
```

Create `src/rules.rs` with:
- `Rule` struct: `pattern: Regex`, `style: owo_colors::Style`, `scope: MatchScope`, `priority: usize`
- `MatchScope` enum: `Line`, `Match`, `Capture(usize)` (Match and Capture are Phase 2 but define now for forward compatibility)
- `parse_rule(input: &str, priority: usize) -> Result<Rule>`: Parse `PATTERN:STYLE[:SCOPE]` using `rsplitn(3, ':')` to handle colons in patterns. If 3 parts: check if last part is a valid scope; if not, treat the split as `PATTERN_WITH_COLON:STYLE` (rejoin first two parts as pattern, last as style). If 2 parts: pattern and style, default scope is Line.
- `default_rules() -> Vec<Rule>`: Built-in log level rules per CONTEXT.md decisions. Use `(?i)` prefix for case-insensitive. FATAL/CRITICAL: bold+red. ERROR: red. WARN: yellow. DEBUG: dimmed. TRACE: use XtermColor(240) for "very dim" to differentiate from DEBUG's dimmed.
- `build_rules(cli_rules: &[String]) -> Result<Vec<Rule>>`: Parse CLI rules with priority starting at 0, then append default rules with priorities starting after CLI rules. This ensures user rules are checked first.

Update `src/lib.rs` to add `pub mod cli; pub mod rules;`

Write unit tests in both modules. For rules.rs, test parse_rule with various inputs including edge cases (colons in patterns, invalid patterns, missing style). For cli.rs, test that Cli struct parses correctly using `clap::Parser::try_parse_from`.
  </action>
