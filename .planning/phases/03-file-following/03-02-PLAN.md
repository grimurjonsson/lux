  <behavior>

    - FollowMode::Name checks inode identity to detect rotation
    - read_new_lines reads all available data since last position using read_line (not lines() iterator)

    - -f mode: exits when reaching EOF on deleted file (no more events)

    - -F mode file disappears: warns on stderr, polls until reappears
    - Event debouncing: after modify event, drain pending events before reading
  </behavior>
  <action>
    1. Add `pub mod follow;` to src/lib.rs.

    2. Create src/follow.rs implementing:

    ```
    pub enum FollowMode { Descriptor, Name }

    struct FileIdentity { dev: u64, ino: u64 }
    // from_metadata, matches methods

    pub fn run(
        path: &Path,
        mode: FollowMode,
        file: File,           // already-opened file at correct position from initial read
        engine: &Engine,
        writer: &mut BufWriter<impl Write>,
    ) -> anyhow::Result<()>
    ```

    3. Event loop architecture:
       - Use `notify::recommended_watcher` with `mpsc::channel`
       - For Descriptor mode: watch the file directly
       - For Name mode: watch the parent directory (NonRecursive) to detect file creation after rotation
       - `recv_timeout(Duration::from_millis(250))` for periodic fallback checks
       - On Modify event: call read_new_lines (read_line loop until 0 bytes)
       - On timeout: check for copytruncate (file size < position) and rotation (inode changed)

    4. Descriptor mode (-f) specifics:
       - File must already be open (caller validates existence)
       - Keep reading from the same fd
       - When file is deleted, the fd remains valid -- keep reading until EOF
       - After final EOF with no more events (watcher disconnected or no new events for several timeouts), exit cleanly
       - Do NOT check inode identity (follow the fd, not the path)

    5. Name mode (-F) specifics:
       - After each event/timeout, stat the path and compare inode identity with open fd
       - If inode differs: rotation happened -- drain remaining lines from old fd, open new file from beginning, update watcher if needed
       - If path doesn't exist (stat fails): file disappeared -- eprintln warning "ctail: '{path}' has been replaced; following new file" on rotation, "ctail: '{path}' has disappeared; waiting..." on disappearance
       - Poll at 1-second intervals when file is missing
       - On reappearance: eprintln notice, open new file, resume following

    6. Copytruncate detection (both modes, but especially relevant for Name mode):
       - Before each read attempt, check `file.metadata()?.len()` vs current position
       - If file size < current seek position: file was truncated, seek to 0, read from beginning

    7. read_new_lines helper:
       - Use `BufReader::read_line()` in a loop (NOT `lines()` iterator which terminates at EOF)
       - On `Ok(0)`: EOF, break and return
       - Trim trailing newline/carriage return before passing to engine.apply()
       - Write colorized output with `writeln!` to BufWriter, flush after batch

    8. Key anti-patterns to avoid (from research):
       - Do NOT use `lines()` iterator for following (terminates at EOF)
       - Do NOT watch the file directly in -F mode (watch parent directory)
       - Do NOT busy-poll without sleep (use notify events with timeout fallback)
       - Do NOT reopen file on every read (keep fd open, only reopen on rotation)

    9. Unit tests for FileIdentity (from_metadata, matches with same/different inodes).
       Other behaviors are best tested via integration tests (Task 2).

    Note on debouncing (macOS kqueue duplicate events): After receiving any Modify event, drain all pending events from the channel with `try_recv()` before reading. This handles the kqueue NOTE_WRITE + NOTE_EXTEND double-fire issue.

            // Done -- return without following
        } else {
            // -F or bare file: follow by name, file may not exist yet
            match std::fs::File::open(path) {
                Ok(mut file) => {
                    let initial = read_initial(&mut file, &line_spec)?;
                    print_lines(&initial, &engine, &mut writer)?;
                    follow::run(path, follow::FollowMode::Name, file, &engine, &mut writer)?;
                }
                Err(e) if e.kind() == std::io::ErrorKind::NotFound => {
                    eprintln!("ctail: '{}' does not exist; waiting for it to be created...", file_path);

                }
                Err(e) => return Err(e).with_context(|| format!("cannot open '{file_path}'")),
